- `themes/yaotemp/css/design.scss`
- `themes/yaotemp/css/design.css`
- `themes/yaotemp/js/design.js`
- 共通パーツ調整が必要な場合は既存 `header.php` / `footer.php` / `sidebar.php` を直接改修せず、まずトップ専用CSSで吸収する

## ルール要約

- トップページは `home.php` で実装する
- 投稿やカスタム投稿の動的取得は行わず、静的HTMLでUIを再現する
- 画像は `themes/yaotemp/img/draft` から必要分だけ `themes/yaotemp/img` 直下へコピーして使う
- トップ専用画像は `top-` 接頭辞を付ける
- 共通パーツ用画像には `top-` を付けない
- 画像パスは `<?php bloginfo('template_url');?>/img/xxx.jpg`
- スライダーを使う箇所は `slick slider` を使う
- `1000px` 以下でレスポンシブが成立し、横スクロールや重なりが出ないこと

## デザイン全体の方向性

- ベースは白からごく薄い生成りの余白を大きく使う
- 明朝体を主役にしつつ、細めの和文テキストで静かな印象を維持する
- セクション間の余白はかなり広い
- ボタン色はグレージュ系 (`#a89f90` 近辺)
- PCは縦書きテキストを複数箇所で使う
- SPは情報量を減らさず、縦書き要素を必要箇所だけ残す

## セクション構成

1. ヘッダー
   PC: 左ロゴ、中央ナビ、右に資料請求/問い合わせ系のグレージュボタン
   SP: 左ロゴ、右ハンバーガー

2. KV
   大見出しは画像上端に少しかかる構成
   右上に小さなリード文
   左端に縦向きの英字補助テキスト
   メイン画像は木の室内写真

3. News
   シンプルな1行ニュース
   見出し `News` と日時/文言を横並び

4. Intro
   薄い図面背景のある生成りエリア
   PCはタイトル・本文とも縦書き
   SPはタイトル縦書き、本文も縦組み寄りで見せる

5. 4分割導線
   `Support / Story / Window / Region`
   2 x 2 グリッド
   画像の上に白文字
   画像自体に文字入り素材を使っているので、実装では余計な文字重ねは不要

6. Event
   小見出し `・Event`
   3カラムカード
   各カードは画像、カテゴリ、タイトル、日付行2段
   下に `もっとみる` ボタン

7. Concept
   左に小見出しと本文、右に写真2枚を段違い配置
   背景は薄い生成り

8. Homemaking
   セクション見出しと短い導入文
   続いて左右交互の大きな説明ブロック2本
   1本目: 注文住宅
   2本目: リフォーム・リノベーション

9. Portfolio / User's voice
   3カラムカード
   画像、カテゴリ、所在地、見出し、短文
   下に `もっとみる`

10. Gallery
   横長のスライダー
   PCは3枚見え
   SPは1枚見え寄り
   右下に前後矢印

11. Support / Careers
   2カラムの大きな画像バナー
   画像の上に白文字の説明

12. Area
   左に地図画像、右に対応エリアテキスト
   見出し `・Area`
   エリア名ごとに区切り線

13. FAQ
   角丸の大きな薄色ボックス内
   Q/Aが縦に並ぶ
   下に `もっとみる`

14. Blog / Column
   2カラム
   各カラムに記事3件
   サムネイル小、日時、タイトル
   各カラム下に `もっとみる`

15. Footer直前CV
   4分割の横並び導線
   `資料請求 / お問い合わせ / お電話 / LINE相談`
   PCは横4分割、SPは縦積み

16. Footer
   薄い生成り背景
   中央寄せロゴ、住所、SNS
   下に複数列のリンク

## 画面別メモ

### PC

- コンテンツ幅は概ね `1200px` 前後が基準
- ただしKVとギャラリーは画面いっぱいに近い見せ方
- 固定サイド導線は右端に細めのボックスで出す

### SP

- 余白は左右 `16px` 前後が基準
- 先頭付近に `CONTACT` と `LINE` の固定導線が出る
- メニュー開閉時は全面に近いオーバーレイメニュー
- セクションの順序はPCと同じ

## 先に共通化しておくとよい要素

## 注意点

- 既存テーマの共通ヘッダー/サイドバーがトップ再現を邪魔しやすい
- `main` や `body` に既存テーマの幅/余白指定があるため、トップ専用で明示的に上書きする
- `design.js` には既存処理が多いので、トップ専用のJS追加は影響範囲を狭くする
- `modaal` は未読込状態でもエラーにならないよう存在チェックを入れて扱う
